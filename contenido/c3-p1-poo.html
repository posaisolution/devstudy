Los 4 pilares, sin palabras raras

La pregunta 2 del examen pide "al menos 4 pilares". Estos son los cuatro que siempre se preguntan. Toca cada uno y léelo en voz alta: si puedes explicarlo con tus palabras, ya lo sabes.

Idea clave

Abstracción: quedarte con lo importante

Es modelar solo lo que tu programa necesita y esconder el resto del detalle. Cuando manejas un carro no necesitas saber cómo funciona el motor por dentro: usas el volante, el freno y el acelerador. Eso es abstraer.

En código: tu clase Vehiculo ofrece mostrar_datos() y quien la usa no necesita saber cómo arma esa cadena por dentro.
class Vehiculo:
    def mostrar_datos(self):
        return f"{self.__modelo} - {self.__potencia} HP"

Encapsulamiento: los datos se cuidan solos

Los atributos se guardan protegidos y solo se modifican por medio de métodos. Nadie de afuera puede cambiarlos a su antojo.

Analogía: el cajero automático. No metes la mano a la caja fuerte; pides dinero con los botones y el cajero decide si te lo da.
class Cuenta:
    def __init__(self, saldo):
        self.__saldo = saldo        # privado

    def retirar(self, monto):
        if 0 < monto <= self.__saldo:
            self.__saldo -= monto

    def obtener_saldo(self):        # getter
        return self.__saldo

En Python, __saldo con dos guiones bajos se vuelve privado y solo se lee por obtener_saldo().

Herencia: reutilizar lo que ya existe

Una clase hija recibe los atributos y métodos de la clase padre, y además agrega lo suyo. Se lee como "es un": un taxi es un vehículo.

En el examen: Taxi y Autobus heredan de Vehiculo, así que ya tienen matrícula, modelo y potencia sin volver a escribirlos.
class Vehiculo:
    def __init__(self, matricula, modelo, potencia):
        self.__matricula = matricula
        self.__modelo = modelo
        self.__potencia = potencia

class Taxi(Vehiculo):      # hereda todo
    pass

Polimorfismo: el mismo nombre, respuestas distintas

Un mismo método se comporta diferente según el objeto que lo ejecuta. Todos los vehículos tienen mostrar_datos(), pero el taxi muestra su licencia y el autobús sus asientos.

Analogía: todos los animales responden a hablar(), pero el perro ladra y el gato maúlla. Misma orden, distinto resultado.
class Taxi(Vehiculo):
    def mostrar_datos(self):
        return super().mostrar_datos() + " | Licencia: L-9087"

class Autobus(Vehiculo):
    def mostrar_datos(self):
        return super().mostrar_datos() + " | Asientos: 40"

Las dos diferencias que te van a preguntar

ConceptoQué esCómo lo reconoces
Clase El molde, la definición. No ocupa memoria como objeto todavía. Se declara con class y empieza con mayúscula.
Objeto La instancia real creada a partir del molde, con sus propios valores. Nace al llamar Alumno("Ana", "2026001").

Las 6 preguntas de teoría, respondidas

Primero intenta contestar en tu cabeza. Después abre la respuesta y compara. Si tu respuesta se parece en idea, ya vas bien.

1¿Qué es la programación orientada a objetos?

Es un paradigma de programación que organiza el código en objetos. Cada objeto junta dos cosas: sus datos (atributos) y las acciones que puede hacer con esos datos (métodos).

En lugar de escribir funciones sueltas que trabajan con variables sueltas, modelas las cosas del mundo real —un alumno, una cuenta, un taxi— y las pones a colaborar entre sí.

Respuesta corta: es una forma de programar basada en objetos que combinan datos y comportamiento.

2Menciona al menos 4 pilares de la POO
  • Abstracción: modelar solo lo importante y esconder el detalle.
  • Encapsulamiento: proteger los datos y acceder a ellos solo por métodos.
  • Herencia: una clase hija reutiliza y amplía lo de la clase padre.
  • Polimorfismo: el mismo método se comporta distinto según el objeto.

Algunos autores agregan un quinto: la composición (un objeto contiene a otro).

3¿Cuál es la diferencia exacta entre una Clase y un Objeto?

La clase es la definición: el molde que dice qué atributos y métodos va a tener algo. El objeto es la instancia: algo concreto creado a partir de ese molde, que ya vive en memoria y tiene sus propios valores.

La diferencia está en la palabra exacta: la clase describe, el objeto existe. Una clase Alumno puede generar mil objetos Alumno, todos con distinto nombre y matrícula, pero con la misma estructura.

Analogía: el molde de galletas es la clase; cada galleta es un objeto.

4¿Cuál es la diferencia de rol entre un Atributo y un Método?

El atributo guarda el estado: es un dato del objeto y responde a qué es o qué tiene. El método define el comportamiento: es una acción y responde a qué hace.

En una cuenta bancaria, saldo y titular son atributos; depositar() y obtener_saldo() son métodos.

Truco: atributo = sustantivo, método = verbo con paréntesis.

5¿Para qué sirve super() y qué pasa si lo omites?

Propósito: llamar al constructor de la clase padre desde la subclase, para que inicialice los atributos heredados y no tengas que repetir ese código.

Si lo omites: el constructor del padre nunca se ejecuta, los atributos heredados no se crean, y al usarlos el programa lanza un AttributeError. En Python la llamada no es automática.

6¿Qué es el polimorfismo y cómo se manifiesta?

Es la capacidad de que un mismo método (mismo nombre) se comporte de forma distinta según el objeto que lo ejecuta.

Cómo se manifiesta: principalmente por sobrescritura (override) dentro de una jerarquía de herencia. La clase padre define mostrar_datos() y cada hija lo redefine a su manera. 

for v in [taxi, autobus]:
    print(v.mostrar_datos())   # mismo metodo, distinto resultado

Un método, dos objetos, dos respuestas. Eso es polimorfismo.

Código de las tres clases

class Vehiculo:
    def __init__(self, matricula, modelo, potencia):
        self.__matricula = matricula
        self.__modelo = modelo
        self.__potencia = potencia

    # metodos de acceso
    def get_matricula(self):
        return self.__matricula

    def get_modelo(self):
        return self.__modelo

    def get_potencia(self):
        return self.__potencia

    def mostrar_datos(self):
        return (f"Matricula: {self.__matricula} | "
                f"Modelo: {self.__modelo} | Potencia: {self.__potencia} HP")


class Taxi(Vehiculo):
    def __init__(self, matricula, modelo, potencia, numero_licencia):
        super().__init__(matricula, modelo, potencia)
        self.__numero_licencia = numero_licencia
        self.__viajes = []

    def registrar_viaje(self, costo):
        if costo <= 0:
            print("Error: el costo debe ser mayor que cero.")
            return
        self.__viajes.append(costo)
        print(f"Viaje registrado: ${costo}")

    def pago_total(self):
        total = sum(self.__viajes)
        print(f"Pago total del dia: ${total}")

    def mostrar_datos(self):
        base = super().mostrar_datos()
        return f"{base} | Licencia: {self.__numero_licencia}"


class Autobus(Vehiculo):
    def __init__(self, matricula, modelo, potencia, numero_asientos):
        super().__init__(matricula, modelo, potencia)
        self.__numero_asientos = numero_asientos
        self.__pasajeros_actuales = 0

    def subir_pasajeros(self, cantidad):
        if cantidad <= 0:
            print("Error: cantidad invalida.")
            return
        libres = self.__numero_asientos - self.__pasajeros_actuales
        if cantidad > libres:
            print(f"Solo quedaban {libres} asientos. Se subieron {libres}.")
            self.__pasajeros_actuales = self.__numero_asientos
        else:
            self.__pasajeros_actuales += cantidad
        print(f"A bordo: {self.__pasajeros_actuales}")

    def diagnostico(self):
        libres = self.__numero_asientos - self.__pasajeros_actuales
        print(f"A bordo: {self.__pasajeros_actuales} | Libres: {libres}")

    def mostrar_datos(self):
        base = super().mostrar_datos()
        return f"{base} | Asientos: {self.__numero_asientos}"
Cómo se usa
taxi = Taxi("ABC-123", "Tsuru", 115, "L-9087")
autobus = Autobus("BUS-45", "Volvo", 280, 40)

taxi.registrar_viaje(120)
taxi.registrar_viaje(85)
taxi.pago_total()

autobus.subir_pasajeros(25)
autobus.diagnostico()

for v in [taxi, autobus]:
    print(v.mostrar_datos())   # polimorfismo
Lo que revisan: atributos privados con __, getters, super() en ambas hijas, validaciones en los métodos propios y mostrar_datos() sobrescrito reutilizando el del padre.

Empleado con aumento por edad

Una clase con nombre, apellido, edad y salario. Si el empleado tiene más de 40 años, recibe un aumento.

class Empleado:
    def __init__(self, nombre, apellido, edad, salario):
        self.nombre = nombre
        self.apellido = apellido
        self.edad = edad
        self.salario = salario

    def aumento(self, monto):
        if self.edad > 40:
            self.salario += monto
            print(f"Nuevo salario de {self.nombre}: ${self.salario}")
        else:
            print("Sin aumento del salario")

    def datos(self):
        print(f"{self.nombre} {self.apellido} - {self.edad} anios - ${self.salario}")


def main():
    empleado1 = Empleado("Enrique", "Meza", 20, 2000)
    empleado1.edad = 41            # ajuste: ahora ya supera los 40
    empleado1.aumento(500)
    empleado1.datos()

    empleado2 = Empleado("Julio", "Preciado", 45, 4500)
    empleado2.aumento(500)
    empleado2.datos()

main()
Cuidado: en la versión original, el else hacía self.salario = 0. Eso borra el sueldo del empleado. Lo correcto es no tocarlo y solo avisar que no hay aumento.
Ejercicio 2

Libro, Usuario y LibroDigital

Préstamos con encapsulamiento del ISBN y polimorfismo en disponible().

class Libro:
    def __init__(self, titulo, autor, isbn):
        self.titulo = titulo
        self.autor = autor
        self.__isbn = isbn        # privado: no cambia
        self.prestado = False

    @property
    def isbn(self):
        return self.__isbn

    def disponible(self):
        return not self.prestado


class LibroDigital(Libro):
    def disponible(self):         # polimorfismo
        return True               # un digital siempre esta disponible


class Usuario:
    def __init__(self, nombre):
        self.nombre = nombre
        self.libros_prestados = []

    def pedir_prestado(self, libro):
        if libro.disponible():
            libro.prestado = True
            self.libros_prestados.append(libro)
            print(f"{self.nombre} tomo '{libro.titulo}'")
        else:
            print(f"'{libro.titulo}' no esta disponible")

    def devolver(self, libro):
        if libro in self.libros_prestados:
            libro.prestado = False
            self.libros_prestados.remove(libro)
            print(f"{self.nombre} devolvio '{libro.titulo}'")
Concepto que demuestra: @property deja leer el ISBN pero no modificarlo, y LibroDigital cambia el comportamiento de un método heredado.

Producto con IVA, @classmethod y @staticmethod

Aquí se demuestra la diferencia entre atributo de clase y atributo de instancia.

class Producto:
    iva = 0.16                        # atributo de CLASE

    def __init__(self, nombre, precio, stock):
        self.nombre = nombre          # atributos de INSTANCIA
        self.precio = precio
        self.stock = stock

    def mostrar(self):
        print(f"{self.nombre} | ${self.precio} | Stock: {self.stock}")

    def vender(self, cantidad):
        if cantidad <= self.stock:
            self.stock -= cantidad
            print(f"Vendidas {cantidad} de {self.nombre}")
        else:
            print(f"Stock insuficiente de {self.nombre}")

    @classmethod
    def crear_desde_texto(cls, texto):
        nombre, precio, stock = texto.split(",")
        return cls(nombre.strip(), float(precio), int(stock))

    @staticmethod
    def calcular_total(precio, cantidad):
        return precio * cantidad

Ejercicio 4

CuentaBancaria encapsulada

Saldo privado, validación de montos y transferencia entre cuentas como reto extra.

class CuentaBancaria:
    def __init__(self, titular, numero_cuenta, saldo, tasa_interes):
        self.titular = titular
        self.numero_cuenta = numero_cuenta
        self.__saldo = saldo                  # privado
        self.tasa_interes = tasa_interes

    def depositar(self, monto):
        if monto > 0:
            self.__saldo += monto
        else:
            print("Error: el monto debe ser positivo")

    def retirar(self, monto):
        if monto <= 0:
            print("Error: el monto debe ser positivo")
        elif monto > self.__saldo:
            print("Error: saldo insuficiente")
        else:
            self.__saldo -= monto

    def calcular_interes(self):
        self.__saldo += self.__saldo * self.tasa_interes

    def obtener_saldo(self):                  # getter
        return self.__saldo

    def transferir(self, destino, monto):
        if 0 < monto <= self.__saldo:
            self.__saldo -= monto
            destino.depositar(monto)
        else:
            print("Error: no se puede transferir ese monto")


c1 = CuentaBancaria("Enrique", 1, 5000, 0.05)
c2 = CuentaBancaria("Julio", 2, 2000, 0.03)

c1.depositar(1500)
c1.retirar(2000)
print(c1.obtener_saldo())

c2.calcular_interes()
print(c2.obtener_saldo())

c1.transferir(c2, 1000)
print(c1.obtener_saldo(), c2.obtener_saldo())
Lo que demuestra: nadie puede escribir c1.__saldo desde afuera; todo pasa por depositar(), retirar() y obtener_saldo().
Ejercicio 5

Empleado, Vendedor y Gerente

Herencia con dos hijas y un método que se reutiliza con super().

class Empleado:
    def __init__(self, nombre, sueldo_base):
        self.nombre = nombre
        self.sueldo_base = sueldo_base

    def mostrar_datos(self):
        return f"Nombre: {self.nombre} - Sueldo base: ${self.sueldo_base}"


class Vendedor(Empleado):
    def __init__(self, nombre, sueldo_base, meta_ventas, ventas_realizadas):
        super().__init__(nombre, sueldo_base)
        self.meta_ventas = meta_ventas
        self.ventas_realizadas = ventas_realizadas

    def calcular_pago(self):
        if self.ventas_realizadas >= self.meta_ventas:
            bono = self.sueldo_base * 0.10
            return self.sueldo_base + bono
        return self.sueldo_base

    def mostrar_datos(self):
        return (f"{super().mostrar_datos()} - Meta: {self.meta_ventas} - "
                f"Vendido: {self.ventas_realizadas}")


class Gerente(Empleado):
    def __init__(self, nombre, sueldo_base, departamento, bono_gerencial):
        super().__init__(nombre, sueldo_base)
        self.departamento = departamento
        self.bono_gerencial = bono_gerencial

    def calcular_pago(self):
        return self.sueldo_base + self.bono_gerencial

    def mostrar_datos(self):
        return f"{super().mostrar_datos()} - Departamento: {self.departamento}"


v1 = Vendedor("Sebastian", 500, 1000, 1100)   # supera la meta: lleva bono
v2 = Vendedor("Ricardo", 500, 1000, 900)      # no llega: sueldo base
g1 = Gerente("Julio", 4000, "Ventas", 500)

print(v1.calcular_pago())
print(v2.calcular_pago())
print(g1.calcular_pago())
print(v1.mostrar_datos())
El patrón: el padre define mostrar_datos(), cada hija lo amplía con super().mostrar_datos() y agrega lo suyo. Igual que en el examen.
